예측을 병상 운영에 연결하는 방법

대기 환자 한 명의 ICU 입실을 준비합니다. LINK 제안 하나와 기존 큰 병동 지도를 연결해 확인할 병상과 다음 작업을 보여줍니다. 원본 기록은 유지하고, 지도에 가상 배치만 임시 표시합니다.

현재 범위: 규칙 기반 운영 시뮬레이션. 가상 기록·시간별 예측값을 사용하며 실제 LLM·Qwen·모델 추론은 연결하지 않았습니다. 직원 호출, 실제 병상 예약, EMR 변경도 수행하지 않습니다.

대기 환자 한 명의 입실을 준비하는 이야기 Decision workflow

01 · 입실 요청준비할 일 확인대기 환자와 병상 현황 조회
02 · 환자·예측같은 병상 환자 확인현재 조회 시점과 가상 예측
03 · 추가 확인회신에 맞춰 재조회전실 결정 기록·수용·이송·자원
04 · 보고 준비확인 결과 모으기근거와 다음 작업의 양식 초안
05 · 사람 검토작업 순서 승인자동 진행을 멈추고 검토 대기
06 · 입실 준비완료를 차례로 확인이동 → 정리 → 예약 → 입실
예측 ≠ 공실. 예상 퇴실까지 남은 시간이 짧아도 현재 병상은 사용 중입니다. 운영 승인 역시 전실 완료가 아니며, 병상 정리와 준비 확인 전에는 가용 병상으로 계산하지 않습니다.

발표에서 보여줄 한 장면 One patient, one admission

A병원 SICU에서 ‘흐름 보기’를 펼치고 ‘자동 시연’ 또는 제안 카드의 행동 버튼으로 시작합니다. LINK가 큰 지도에서 03번 검토 병상·보고·승인 위치를 짚으며 다음 확인 하나를 제안합니다. 격리 재입실 상황은 02번 병상을 검토합니다. 별도 축소 지도나 R/A 소개 카드는 없습니다.

회신에 따라 다음 확인을 바꿉니다

수용 병동 취소를 확인하면 진행을 멈추고 수용 확인을 다시 조회합니다. 새 확인 기록이 도착하면 현재 시점 환자 자료도 재조회해 보고를 수정합니다. 사람이 작업안을 승인해야 전실·정리·예약·입실로 진행합니다.

도움과 한계를 같은 사례에서 확인합니다.
도움: 필요한 조회와 준비 순서를 연결하고 근거가 붙은 보고를 모읍니다.
한계: 수용 불가·미확인 조건은 그대로 남기며, 예측값이 임상 전실 결정을 대신하지 않습니다.

현재: 정해진 규칙이 로컬 조회 결과에 따라 분기하는 동작 시뮬레이션. 확장 목표(Planned): LLM의 도구 선택·재확인과 실제 원천 시스템 연결. 현재 화면의 자동 재생을 실제 LLM 에이전트가 수행한 것으로 소개하지 않습니다.

조건 검사다음 작업 제안사람 승인변경 시 재계획판단 이력
예측값의 의미
원내 사망 위험(%)과 일반병동 전실까지 남은 일수는 화면 시연용 가상 예시입니다. 잔여 일수는 병원 퇴원까지의 시간이나 퇴실 가능 확률이 아닙니다.
연구 모델 calmrl_v19_fixed24는 첫 24시간의 EMR로 ICU 입실 24시간 시점의 원내 사망 위험과, 생존해 일반병동으로 전실한 사례의 퇴실 잔여 일수를 예측합니다. 흉부 X선은 예측 시점 이전 72시간 이내의 동일 환자 영상입니다. 24시간과 72시간은 입력 자료 기준이며, 향후 24시간 내 사망이나 72시간 내 전실 확률을 뜻하지 않습니다. 이 공개 데모는 해당 모델을 실행하지 않습니다.

예외가 생기면 Exception handling

  • 누락·오래된 정보: 미확인으로 표시하고 담당자에게 확인할 항목을 남깁니다. 누락을 정상·준비 완료로 간주하지 않습니다.
  • 승인 뒤 조건 변경: 진행을 멈추고 보류 사유를 남깁니다. 다시 진행하려면 담당자가 조건을 재확인해야 하며, 이전 승인을 새 조건에 자동 적용하지 않습니다.
  • 실행 실패·중복 요청: 완료를 확인하기 전에는 완료 처리하지 않고, 병상 담당자가 중복·취소 여부를 확인합니다.
